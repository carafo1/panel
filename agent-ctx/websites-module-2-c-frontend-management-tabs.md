- **Files modified:** `/src/components/hosting/hosting-panel.tsx` (added import block + 6 component renders inside `ProjectDetailView`)
- **Key decisions:**
  - Followed the existing stacked-Card pattern instead of forcing a `<Tabs>` component, since `ProjectDetailView` already uses Cards and the spec said "follow the existing pattern" if not Tabs. Each new component is wrapped in its own `<Card>` so it slots in naturally.
  - Used **SVG sparklines** (no Recharts) for the resource history charts to keep the bundle small and avoid ChartContainer context plumbing — the 24h history data is simple enough that a 50-line `<polyline>` is clearer than a full Recharts chart.
  - Used **XHR** for file upload so we get real `upload.onprogress` events for the progress bar (fetch doesn't support upload progress without streaming).
  - Used the **blob approach** for backup/file downloads so the Authorization header is sent (browser `window.open()` can't attach headers).
  - Per-row password reveal (`?reveal=true` per DB) rather than global toggle — matches the security best practice of only revealing what's requested.
  - Terminal cleanup on unmount is best-effort (fire-and-forget DELETE) so navigation away doesn't block.
  - Domain delete is **disabled** when the domain is primary (must demote first) — matches the spec.
- **Lint result:** `bun run lint` reports **0 errors and 0 warnings** in my new file (`website-management-tabs.tsx`) and in my modifications to `hosting-panel.tsx`. The 4 remaining lint errors in the project are all pre-existing in `create-website-wizard.tsx` (owned by another subagent) and unrelated to this task.
- **Dev server:** No new errors in `dev.log`. Page renders 200 OK.
- **Caveats:**
  - The 6 new endpoints (`/api/hosting/[id]/{databases,backups,files,terminal,resources,domains}`) are being built by the Backend subagent in parallel. The frontend assumes the documented response shapes; if the backend deviates, the components will show appropriate error/empty states rather than crash (all fetches are wrapped in try/catch with toast notifications).
  - The TerminalTab session lifecycle assumes a single session per mount. If users navigate away and back, a new session is created (the old one is closed via DELETE on unmount). This is the documented behavior.
  - The FilesTab editor truncates files >backend's threshold; the UI shows a "(truncated)" warning and the user can still edit+save the visible portion (per spec).
